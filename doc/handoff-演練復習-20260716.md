**復習重點 / 踩坑**：

### Chapter10 — 兩版 HookHub 部署演練（S1 分析、S4 部署）

| 項目 | 內容 |
| ------ | ------ |
| Sample code | `Chapter10/v1-zealous-jemison/hookhub/`（PORT 3002，路徑 `/ch10`）、`Chapter10/v2-vigilant-feistel/hookhub/`（PORT 3003，路徑 `/v2`，`next.config.ts` 有 `basePath: "/v2"`） |
| 版本差異 | 程式碼同構；v1=後期迭代（真實星數 ⭐17400+）、v2=早期迭代（80+ 行 CSS 動畫）。**不是 bug 修正關係**，是同功能不同 session 迭代 |
| memory 教材 | 兩版各有 `memory/spec/`、`memory/frontend/` 的 `CLAUDE-中文.md`（產品規格書 + 前端 persona） |
| CI/CD | `.github/workflows/deploy-hookhub-ch10.yml`（v1）、`deploy-hookhub-ch10-v2.yml`（v2），三條線共用 `concurrency: group: vps-deploy` |

**復習重點 / 踩坑（本章最精華）**：

- **nginx `proxy_pass` 尾斜線**：有尾斜線 = path rewriting（剝掉 location 前綴）；無尾斜線 = 保留完整 URI。搭配 Next.js `basePath` 必須用**無尾斜線**
- Next.js 會把 `/v2/` 308 重定向到 `/v2` → health check 必須打**不含尾斜線**的路徑
- health check 用 `curl -w "%{http_code}"` + 明確判斷 `= 200`（`curl -f` 不能保證 200）
- `next.config.ts` 都要 `outputFileTracingRoot: __dirname`——`%USERPROFILE%\package-lock.json` 會讓 Next.js 誤判 workspace root，影響 Tailwind PostCSS
- PM2 `ecosystem.config.js` 設 `HOSTNAME=127.0.0.1`（loopback only，由 nginx 對外）
- v1 vs v2 是「nginx 尾斜線改寫」vs「basePath」**兩種路由策略的對照教材**
