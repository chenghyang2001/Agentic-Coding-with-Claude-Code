### 3.2 三條 VPS 部署 workflow 修正（走 code-writer → code-qa → code-reviewer 兩輪）

檔案：`.github/workflows/deploy-hookhub.yml`（Ch02）、`deploy-hookhub-ch10.yml`（v1）、`deploy-hookhub-ch10-v2.yml`（v2）

| 修正 | 原因 |
| --- | --- |
| Ch02 加 `concurrency: group: vps-deploy` | 三線共用同一 VPS clone，避免同時部署互撞 |
| Ch02 `git pull --ff-only` → fetch + `reset --hard FETCH_HEAD` | VPS 是乾淨鏡像；ff-only 遇本地修改會 abort |
| Ch02 `command_timeout` 10m → 15m | 低規 VPS 的 npm ci + build 實測 8-10 分鐘 |
| Ch02 `pm2 list \| grep -q hookhub` → `pm2 describe hookhub` | 子字串會誤命中 `hookhub-ch10` / `hookhub-v2` |
| **三線**：`cd && git fetch && git reset` 拆成三行 | `&&` 串列中間失敗不觸發 `set -e` → fetch 失敗會建舊版且 CI 綠燈（QA 本機實證） |
| **三線**：加 `workflow_dispatch` | 被 concurrency 取消時可手動補跑 |
| **三線**：job 層 `timeout-minutes: 20` | 避免卡住時佔用 group 長達預設 360 分鐘 |
| **三線**：改正 concurrency 註解、刪除錯誤 commit 引用 | 原註解「確保每次 push 都能部署」是錯的 |

部署結果（commit `0bdeb33`）：

| 部署線 | 結果 |
| --- | --- |
| Deploy HookHub to VPS（Ch02，`http://187.127.109.145/`） | ✅ success |
| Deploy HookHub Ch10-v2 to VPS（`/v2`） | ✅ success |
| Deploy HookHub Ch10 to VPS（v1，`/ch10`） | 被 concurrency **cancelled**（正是本次修的語意）→ 等排隊清空後 `gh workflow run deploy-hookhub-ch10.yml` 補跑 → ✅ success |

補跑口訣：**group 內沒有 queued/pending 的 run 才補跑**，否則補跑的 run 會反過來取消別條。

```bash
gh run list --limit 6 --json databaseId,workflowName,status,conclusion -q '.[] | "\(.databaseId) \(.workflowName) \(.status) \(.conclusion)"'
gh workflow run <檔名>.yml --ref main
```

### 第 2 站：Ch03 Custom Commands

- **本質**：`.claude/commands/xxx.md` → 輸入 `/xxx` 時檔案內容當 prompt 送出，`/xxx 後面的字` 填入參數。

## 9. 常見問題排除

| 症狀 | 處理 |
| --- | --- |
| `git ls-files` 中文檔名變成 `\346\...` | 加 `git -c core.quotepath=false` |

| `claude-md-improver` 叫不出來 | §1.4 重裝 plugin + `/reload-plugins` |
